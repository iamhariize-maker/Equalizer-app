BEFORE YOUR FIRST LISTEN

Good questions.

An early beta, with room to grow.
Here’s what to expect.

Will it work with my music app?+

Svan applies EQ to eligible Android audio sessions. Reach depends on your phone, player and output. Start with System effects and use Hi-Fi’s “Is it working?” view to check the connection.

Live Svaresa analysis needs the experimental Audiophile engine and playback the player allows Android to capture. Capture-blocked apps cannot use that engine.

Read the compatibility notes ↗︎
Do I need root or Shizuku?+

No root is needed. Fresh installs start with System effects, a flat curve and 0 dB preamp. Shizuku is an optional setup helper for music detection when a player is unreachable; it isn’t required to open the app.

Read the setup guide ↗︎
Is Svaresa a trained AI model?+

Svaresa is an on-device, rule-based controller today. It uses available measurements and explicit limits. Live tone corrections need capturable playback; System effects uses volume, output and time-of-day context.

What should I know about the Audiophile engine?+

It is experimental. It captures permitted playback, processes it through Svan’s 64-bit DSP chain and plays it back. Android asks for capture permission for each session. It can add delay, particularly over Bluetooth, and delay or echo has been reported on one phone.

Use System effects if that happens. The capture engine cannot provide bit-perfect or USB DAC passthrough.

Does my audio leave my phone?+

Svan processes audio locally and does not upload captured playback. Headphone data is downloaded from GitHub when requested. Logs and screenshots are shared only if you choose to share them.

Read the beta privacy notes ↗︎
Is the beta free? Is the code open source?+

The beta is free for personal evaluation. The code is publicly readable on GitHub, but the original Svan code is All rights reserved. Third-party data, code and fonts retain their own licences.

How can I help shape Svan?+

Try it with your phone, player and headphones. Report your Android version, output route, selected engine and what you heard. Even a report that processing didn’t work is useful. Listener preference and device compatibility are still being evaluated.

DEVELOPMENT UPDATE / 7 OCTOBER 2026

More control.
Clearer evidence.

These changes are in the audio-quality development preview, not the public-beta download below. Release qualification is still in progress.

  • Backing vocals and Binaural in the first Orchestral amplifier row, with clearer per-player descriptions of native processing, system-effects approximations and unavailable controls.
  • Bass Resolve and its Svaresa Auto switch, designed to preserve bass-note definition. Real-music listening qualification is still needed.
  • Optional Detailed spatial processing with reported extra latency; Fast remains the default. These controls enhance existing stereo detail, not isolated vocals or added binaural-beat tones.
  • Capture-rate negotiation with Safe 48 kHz as the default, bounded fallback, and rate-aware clips and comparison renders. Reported capture formats do not prove a streaming source or DAC rate; capture is not bit-perfect passthrough.
  • A read-only “How Svaresa decides” view of the compiled rules and bounds. It is not a live decision audit or a trained AI model.
  • Experimental bass unmasking, off by default and never enabled by Auto. Its limited cuts are tested on synthetic signals; music validation is pending.

Phone performance, battery use and isolated loudness- and delay-matched listening checks on TECNO and LG remain pending. Existing screenshots are unchanged and do not demonstrate these new controls. Website design and new screenshot evidence will follow separately.
